# Design: Replace Native Browser Dialogs in Admin UI

Generated by /office-hours on 2026-05-17
Branch: main
Repo: claude-code-mux
Status: APPROVED
Mode: Builder

## Problem Statement

`src/server/admin.html` uses native browser dialogs throughout:

- 1x `alert()` — inside `notify()` as a UIkit fallback
- 5x `confirm()` — delete provider, delete model, restart server, save-and-restart, delete OAuth token
- 1x `prompt()` — API key entry on 401 in `apiFetch()`

**Root cause discovered during office hours**: UIkit JS was never imported — only
the franken-ui CSS is loaded. So `typeof UIkit === "undefined"` is always true and
`alert()` fires every time `notify()` is called. The UIkit notification path is dead
code. All 7 native dialog calls are the actual live paths.

## What Makes This Cool

The fix is almost free. The UIkit notification and modal APIs are already wired up
correctly in the code — they just need the JS to be present. Adding two `<script>`
tags makes `notify()` work as intended. The confirm/prompt replacements are
mechanical async replacements with UIkit's existing modal API.

## Constraints

- No new non-CDN dependencies
- franken-ui CSS is already loaded — UIKit CSS classes are present
- All confirm() call sites are already in `async` functions
- `apiFetch()` is already async
- Must not change any API or state management logic

## Premises

1. UIkit JS CDN is appropriate since franken-ui CSS already assumes UIkit conventions
2. Three distinct dialog types need distinct replacements (toast / modal confirm / modal prompt)
3. All callers are already async — no async refactor needed beyond the await keyword
4. The grammar bug in `saveAndRestart()` confirmation message should be fixed in-pass

## Approaches Considered

### Approach A: Add UIKit JS (chosen)
Add 2 UIKit CDN script tags. notify() works immediately. Replace confirm() with
`UIkit.modal.confirm()` + try/catch. Replace prompt() with `UIkit.modal.prompt()`.
Effort: S | Risk: Low

### Approach B: Custom vanilla toast + modal
Write ~80 lines of vanilla JS. Zero new CDN dep. Full control, accessibility work needed.
Effort: M | Risk: Low

### Approach C: Inline context feedback
Inline confirmation micro-UIs per-site. No floating elements. Hard to do consistently.
Effort: L | Risk: Medium

## Recommended Approach

**Approach A — Add UIKit JS.**

The notification code is already written correctly. The UIkit modal API is the right
tool: it returns a Promise, is animated, accessible, and consistent with the existing
design system. The cost is two `<script>` tags and `await` at 6 call sites.

**CDN pinning note**: The script tags below use `uikit@3` (floating major). For an
admin-only UI this is an accepted operational risk. Pin to a specific version
(e.g. `uikit@3.21.4`) if stability is a concern.

## Implementation Plan

### Step 1: Add UIKit JS to `<head>` (after franken-ui CSS)

Icons script dropped — notifications and modals don't use icons (saves ~30KB).

```html
<!-- UIKit JS (required for notifications and modals) -->
<script src="https://cdn.jsdelivr.net/npm/uikit@3/dist/js/uikit.min.js"></script>
```

### Step 2: Simplify `notify()` — remove the dead alert() fallback

Two review changes incorporated: (1) escape message as HTML-safe text — UIkit renders
notification content as HTML, alert() did not; (2) console.error guard for CDN failure.

```javascript
function notify(message, status = "primary") {
    if (typeof UIkit === "undefined") {
        console.error("[notify] UIkit not loaded:", message);
        return;
    }
    UIkit.notification({
        message: escapeHtml(message),
        status: status,
        pos: "top-right",
        timeout: 3000,
    });
}
```

### Step 3: Replace 5x `confirm()` with `UIkit.modal.confirm()`

Pattern (all callers are already async):
```javascript
// BEFORE
if (!confirm("Are you sure?")) return;

// AFTER
try {
    await UIkit.modal.confirm("Are you sure?");
} catch (e) {
    return; // user cancelled
}
```

Call sites:
| Function | Line | Message |
|---|---|---|
| `deleteProvider(index)` | ~2551 | "Are you sure you want to delete this provider?" |
| `deleteModel(index)` | ~2808 | "Are you sure you want to delete this model?" |
| `restartServer()` | ~3803 | "Are you sure you want to restart the server?" |
| `saveAndRestart()` | ~3838 | Fix grammar: "Save all settings and restart. Are you sure?" |
| `deleteOAuthToken(providerId)` | ~4399 | `` `Are you sure you want to delete the OAuth token for "${escapeHtml(providerId)}"?` `` |

### Step 4: Replace `prompt()` in `apiFetch()` with `UIkit.modal.prompt()`

```javascript
// BEFORE
const key = prompt("API key required. Enter your server API key:");
if (key) {
    sessionStorage.setItem("ccm_api_key", key);
    headers["X-Api-Key"] = key;
    return fetch(url, { ...options, headers });
}

// AFTER
const key = await UIkit.modal.prompt("API key required. Enter your server API key:", "");
if (key) {
    sessionStorage.setItem("ccm_api_key", key);
    headers["X-Api-Key"] = key;
    return fetch(url, { ...options, headers });
}
```

`UIkit.modal.prompt()` returns `null` on cancel — the existing `if (key)` guard
handles this correctly. `apiFetch` is already `async` — no function signature change needed.

## Open Questions

- UIKit.modal.prompt() returns null on cancel (matching window.prompt behavior). Verify
  the existing null-check `if (key)` still works correctly — it does.
- UIKit notification uses `status: "primary"` by default. Consider whether the default
  `notify()` call (no status arg) should default to "default" or keep "primary".
- UIKit JS CDN adds ~60KB (cached). Acceptable for an admin UI.

## Success Criteria

- `window.alert` is never called
- `window.confirm` is never called
- `window.prompt` is never called
- Notifications appear as dismissable toasts in the top-right corner
- Delete/restart confirmations show a UIKit modal dialog
- API key entry shows a UIKit prompt modal
- No regressions in save, delete, restart, or OAuth flows

## Failure Modes

| Codepath | Failure scenario | Error handling | User sees |
|---|---|---|---|
| UIkit JS CDN fails to load | notify() called before UIkit defined | console.error guard, returns | Nothing (DevTools only) |
| UIkit.modal.confirm() — cancel/Escape | Promise rejects | `catch(e) { return; }` | Dialog closes, no action |
| UIkit.modal.prompt() — cancel | Returns null | `if (key)` guard | Dialog closes, 401 returned |
| deleteOAuthToken with HTML char in ID | Garbled dialog text | `escapeHtml()` added | Clean escaped text |

No critical gaps — all failure modes handled.
