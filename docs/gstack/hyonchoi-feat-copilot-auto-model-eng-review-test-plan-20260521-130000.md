## Affected Pages/Routes

- POST /v1/messages (non-streaming) — "auto" model resolution via CopilotProvider before forwarding to Copilot API
- POST /v1/messages (streaming, `stream: true`) — same resolution path, different response type

## Key Interactions to Verify

- First "auto" request after server start triggers exactly one /models fetch
- Subsequent "auto" requests within 10-min TTL return cached model without /models call
- "auto" model resolved to `is_chat_fallback` model from /models response
- Non-"auto" models pass through unchanged (no resolution attempted)
- supports_model() returns true for models discovered via /models
- Model rejection (400/403/404) on resolved model triggers cache invalidation + refetch

## Edge Cases

- 429 rate limit on /models with stale cache → serves stale, logs warning
- 429 rate limit on /models with no cache → returns error
- Network error on /models with stale cache → serves stale
- Network error on /models with no cache → returns error
- 401 on /models → force-refresh token, retry once
- Empty data array from /models → returns error
- No model with is_chat_fallback → falls back to is_chat_default
- No model with is_chat_default → falls back to first chat model
- Token change (re-auth) → invalidates cache, refetches
- Concurrent "auto" requests with empty cache → only one /models fetch
- TTL expiry (>10 min) → attempts refresh
- Model deprecated by Copilot → invalidate + refetch on 400/403/404

## Critical Paths

- Cold start → first "auto" request → /models fetch → cache populate → chat/completions → success
- TTL expired → "auto" request → /models refresh fails (429) → stale-serve → chat/completions → success
- Model deprecated → "auto" request → stale model → chat/completions 400 → invalidate → refetch → new model → success
