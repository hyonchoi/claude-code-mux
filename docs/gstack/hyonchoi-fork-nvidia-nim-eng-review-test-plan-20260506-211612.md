## Affected Pages/Routes
- /v1/messages — verify provider-level RPM enforcement, bounded wait behavior, and fallback after wait-timeout.
- /v1/chat/completions — verify OpenAI-compatible path still reaches fallback when provider wait timeout occurs.
- /v1/messages/count_tokens — verify count_tokens is NOT throttled by inference limiter.

## Key Interactions to Verify
- Burst requests against a rate-limited primary provider with fallback mapping configured.
- Provider wait timeout path emits deterministic fallback behavior and clear logs.
- Streaming requests honor bounded wait before stream starts, then fallback on timeout.

## Edge Cases
- rate_limit_rpm = 0 in provider config returns explicit startup/config error.
- No fallback mapping available when wait timeout occurs returns clear provider error.
- Forced provider via X-Provider with throttled provider times out deterministically.

## Critical Paths
- Primary provider under quota -> success without fallback.
- Primary provider over quota + permit before max wait -> success on primary.
- Primary provider over quota + wait timeout -> fallback provider succeeds.
- Primary provider over quota + wait timeout + no fallback -> explicit failure surfaced.
