## Affected Pages/Routes
- /admin?tab=providers&view=add — verify NVIDIA NIM appears in provider selection, can be added with API key auth, and persists through localStorage-backed edits.
- Anthropic-compatible proxy message path — verify a configured `nvidia-nim` provider routes non-streaming and streaming requests through the OpenAI-compatible backend.

## Key Interactions to Verify
- Select the NVIDIA NIM provider card in /admin and save a new provider with API key auth.
- Edit an existing NVIDIA NIM provider and confirm the correct provider type is reselected in the form.
- Save a provider with an explicit base URL override and confirm it persists locally until sync.
- Send a non-streaming request through a model mapped to NVIDIA NIM.
- Send a streaming request through a model mapped to NVIDIA NIM.

## Edge Cases
- Missing API key on NVIDIA NIM provider creation should show a clear validation error.
- Invalid NVIDIA API key should surface a visible provider/API failure, not a silent parse error.
- Host-only base URL vs `/v1` URL behavior should be verified and documented consistently.
- Disabled NVIDIA provider config should not register in the provider registry.
- Unknown provider types should still error after adding the new match arm.

## Critical Paths
- Admin add/edit provider flow: choose NIM -> enter credentials -> save locally -> sync to server.
- Backend routing flow: provider config -> ProviderRegistry dispatch -> OpenAIProvider preset -> `/chat/completions` request -> Anthropic-compatible response.
- Streaming flow: provider config -> ProviderRegistry dispatch -> OpenAIProvider preset -> SSE stream -> client-visible output.
- Failure flow: invalid key or wrong base URL -> provider error handling -> clear operator-visible failure.
