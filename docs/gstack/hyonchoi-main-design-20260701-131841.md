# Design: Normalize mid-conversation `role:"system"` messages via a per-mapping strip rule

Generated by /office-hours on 2026-07-01
Branch: main
Repo: hyonchoi/claude-code-mux
Status: APPROVED
Mode: Engineering (infra bugfix)
Supersedes: hyonchoi-main-design-20260519-175000.md

## Problem Statement

Newer Claude Code payloads (opus-4.8, sonnet-5) emit their SessionStart hook
context as a standalone mid-conversation `{role:"system", content:<str>}` entry
in the `messages` array. When the mux redirects such a request to a target that
does not accept `role:"system"` inside `messages` — sonnet-4.6, or any
non-Anthropic provider — the upstream returns **HTTP 400**, silently breaking the
fallback/routing feature for the exact payload shapes the current default Claude
Code models produce.

Confirmed in code:
- `Message.role` is a plain `String` (`src/models/mod.rs:39`) — nothing validates
  or normalizes it; a `role:"system"` entry deserializes and re-serializes intact.
- `AnthropicCompatibleProvider::send_message` does a verbatim passthrough:
  `req_builder.json(&request)` with the comment *"pass-through, no transformation
  needed!"* (`src/providers/anthropic_compatible.rs:608-609`). The `role:"system"`
  entry goes straight to the upstream `/v1/messages`.
- `Router::route` (`src/router/mod.rs:100`) rewrites `request.model` but never
  touches `request.messages`, so a redirect produces a model/shape mismatch.
- The OpenAI path also leaks it: `openai.rs:759` copies `role: msg.role.clone()`
  verbatim, duplicating the system content on top of the real `system` field.

Evidence: `snapshots/REQUEST-STRUCTURE-DIFF.md` — `sonnet-5.json` `messages[1]` is a
`{role:"system", len 13984}` SessionStart hook entry; `sonnet-4-6.json` carries the
same class of content folded into a user-role `<system-reminder>` text block in
`messages[0]`. Anthropic's own client demotes it to user text, which is the target
shape.

## Status Quo

- Cross-model redirects for opus-4.8 / sonnet-5 payloads 400 whenever the target
  rejects `role:"system"`. Operators see failed fallback with no obvious cause.
- The mux **already** has a per-mapping, config-driven request-sanitization
  mechanism for a sibling problem: `strip_beta_options_from_request`
  (`src/server/mod.rs:294`), controlled by `ModelMapping.strip_beta_options: bool`
  and `strip_specific_beta: Vec<String>` (`src/cli/mod.rs:116-121`), applied in the
  fallback loop at both dispatch sites (`mod.rs:1424` non-streaming, `mod.rs:1695`
  streaming). The loop **restores the pristine request per attempt**
  (`mod.rs:1420-1421`) so each fallback candidate sanitizes independently.

This is the natural home for the fix. The role:system normalization is the same
class of problem — "clean the request to match what this target accepts" — and
should be a sibling rule in that exact machinery, not a new pass in the router.

## Constraints

- Must live inside the per-mapping strip mechanism so it composes with beta
  stripping and respects the per-attempt pristine-restore in the fallback loop.
- Must preserve the SessionStart hook content (it can carry injected instructions
  and context) — normalize the envelope, do not drop the payload.
- Must not hoist content to the top-level `system` field: that field's blocks carry
  `cache_control:{ttl:1h}` (see `SystemBlock.cache_control`, `src/models/mod.rs:65`),
  and appending turn-positional content there would disturb the cache breakpoint.
- Must preserve user/assistant alternation on the Anthropic wire.

## Premises

1. **`role:"system"` inside `messages` is never valid documented Anthropic wire
   format.** The Messages API takes `user`/`assistant` turns; system content lives
   in the top-level `system` field. — Agreed (spec + snapshot evidence).
2. **Demoting it to a user `<system-reminder>` block is lossless.** sonnet-4.6's
   native Claude Code client does exactly this, byte-for-byte. — Agreed.
3. **The trigger should follow the existing config idiom, not a hardcoded
   model-comparison.** The user's steer: make it a per-mapping strip rule
   consistent with `strip_beta_options`, so operators control it per mapping and it
   composes with the existing sanitization. This replaces the original TODO's
   "routed model != requested model || non-Anthropic" condition, which was a proxy
   that leaked (e.g. opus→opus via OpenRouter/z.ai still 400s). — Agreed (this
   session).
4. **Doing nothing is not viable.** opus-4.8 and sonnet-5 are the current default
   Claude Code models; the bug breaks fallback for present-day traffic. — Agreed.

## Approaches Considered

### Approach A: Unconditional normalization in the router
Normalize every `role:"system"` message before dispatch, no config, no
model-compare.
- Effort: S. Risk: Low-Med.
- Pro: one code path; fixes every target at once.
- Con: rejected by the user in favor of the config-driven idiom; changes the
  native same-model happy path with no operator control; wrong home (router
  doesn't own request-sanitization).

### Approach B: Conditional on redirect (original TODO wording)
Normalize only when `routed_model != requested_model` or target is non-Anthropic.
- Effort: S. Risk: Med.
- Pro: minimal behavior change.
- Con: the condition is a proxy for "does the target accept role:system" and
  leaks — opus→opus through a non-tolerant anthropic-compatible provider
  (OpenRouter, z.ai) still 400s. Needs requested-vs-routed + provider-type
  threading into the normalization site.

### Approach C: Provider-declared capability flag
Each provider declares `accepts_system_role_in_messages`; dispatch normalizes when
false.
- Effort: M. Risk: Low.
- Con: trait change + per-provider flags to set and maintain; overkill for a single
  message shape.

### Approach D (RECOMMENDED): Per-mapping strip rule, sibling to `strip_beta_options`
Add `ModelMapping.strip_mid_conversation_system: bool` (`#[serde(default)]`). Add a
`normalize_mid_conversation_system(request: &mut AnthropicRequest)` function
alongside `strip_beta_options_from_request` in `src/server/mod.rs`, gated by the new
flag, called at both dispatch sites right after the beta strip. The transform: for
each `role:"system"` message, wrap its content in `<system-reminder>…</system-reminder>`,
convert to a user text block, merge into the nearest preceding user turn (synthesize
a leading user turn if none precedes), then drop the system message.
- Effort: S. Risk: Low.
- Pro: matches the established config idiom the user pointed to; composes with beta
  stripping; inherits the per-attempt pristine-restore for free; per-mapping control
  means each fallback candidate can normalize independently based on whether that
  target tolerates the shape.
- Con: opt-in per mapping — existing configs that redirect opus→sonnet-4.6 keep
  400ing until the operator sets the flag (see Open Questions on the default).

## Recommended Approach

**Approach D.** It is the smallest change that lands in the correct architectural
home, honors the existing `strip_*` config idiom, and composes with the beta-option
sanitization the mux already performs in the fallback loop. The transform body is
identical work across A/B/C/D; D differs only in *where it lives* (the per-mapping
strip machinery) and *how it is triggered* (config flag, per mapping).

### Implementation sketch (for /plan-eng-review — not built here)

1. `src/cli/mod.rs` — add to `ModelMapping`:
   ```rust
   /// Normalize mid-conversation role:"system" messages (SessionStart hook
   /// context from opus-4.8 / sonnet-5) into a user <system-reminder> block
   /// before dispatch. Targets like sonnet-4.6 and non-Anthropic providers
   /// reject role:"system" inside messages.
   #[serde(default)]
   pub strip_mid_conversation_system: bool,
   ```
2. `src/server/mod.rs` — add `normalize_mid_conversation_system(&mut AnthropicRequest)`
   next to `strip_beta_options_from_request`. Iterate `request.messages`; for each
   `role == "system"`, extract text (both `MessageContent::Text` and
   `Blocks`→Text), wrap in `<system-reminder>…</system-reminder>`, and merge into
   the nearest preceding `role == "user"` message (append as a text block, or
   promote a `Text` content to `Blocks`); if no preceding user turn exists, prepend
   a synthesized user turn carrying the reminder; remove the system message.
   Handle: multiple system messages, content already wrapped (idempotence), empty
   content. Log at `info!` when a normalization occurs.
3. `src/server/mod.rs` — call it at both dispatch sites, gated on
   `mapping.strip_mid_conversation_system`, inside the per-attempt block that
   already restores the pristine request. **The two sites are not symmetric** and
   must be handled individually:
   - Non-streaming (`~1424`): restores `anthropic_beta_header` from
     `original_beta_header` (captured `~1387`). Call the normalizer right after the
     beta strip.
   - Streaming (`~1695`): restores from `incoming_beta_header` (captured `~1575`),
     and **additionally reassigns `anthropic_request.system = request_for_routing
     .system.clone()` at `~1702`**. Place the normalizer so it runs on the final
     `messages`/`system` state — after the `system` reassignment — or confirm the
     reassignment cannot reintroduce or shadow a system-role message. Do not assume
     the two sites share variable names or ordering.
4. Update `config/*.example.toml` (and templates) to set the flag `true` on
   mappings that redirect opus/sonnet-5 to sonnet-4.6 or non-Anthropic targets, so
   the fix is discoverable.

## Open Questions

1. **Default on or off?** `strip_beta_options` defaults `false` (opt-in), so
   consistency argues `strip_mid_conversation_system` defaults `false`. But the
   artifact is never valid wire format, so a `true` default would fix every existing
   config with no operator action. Recommendation: **default `false` for idiom
   consistency, but ship the example configs with it enabled on the affected
   mappings and document the footgun in the README.** Confirm during eng review — a
   `true` default is defensible and arguably safer.
2. **Merge vs. drop.** The user's word was "strip." Recommendation: **merge (preserve
   content as a user `<system-reminder>` block)** rather than drop, to avoid losing
   injected SessionStart context. Flag for confirmation.
3. **OpenAI/Gemini path.** For non-Anthropic targets the same flag should apply, but
   those providers already build their own `system` message from `request.system`
   (`openai.rs:734`). Decide whether normalization runs *before* the OpenAI
   transform (so the merged user block flows through `openai.rs:759` naturally) —
   recommended — or whether the OpenAI transform should additionally skip verbatim
   `role:"system"` copy. Running the shared normalization first is cleaner and keeps
   one code path. **Defense-in-depth note:** the OpenAI transform currently has
   *zero* role validation — `openai.rs:759` copies `role: msg.role.clone()`
   verbatim, so a `role:"system"` message that slips past normalization produces a
   *second* system message in the OpenAI `messages` array (on top of the one built
   at `openai.rs:734`), which OpenAI rejects or orders undefined. Recommendation:
   even with normalization running first, add a cheap guard in `transform_request`
   that skips or folds any residual `role == "system"` message, so a bug in the
   normalizer degrades to "system content merged as user text" rather than a hard
   400. One line of insurance for the shared path.
4. **Idempotence across fallback attempts.** The loop restores the pristine request
   per attempt, so normalization re-runs from scratch each time — no double-wrap
   risk. Confirm this holds at both dispatch sites during review.

## Success Criteria

- A request with a mid-array `role:"system"` message, redirected to a mapping with
  `strip_mid_conversation_system = true`, produces **no `role:"system"` entry** on
  the upstream wire and returns 200 from sonnet-4.6 and from a non-Anthropic target.
- The `<system-reminder>` content is present in the nearest preceding user turn;
  no content is lost.
- Top-level `system` blocks and their `cache_control` are untouched.
- User/assistant alternation is preserved.
- Beta-option stripping still works unchanged when both flags are set on a mapping.
- Unit tests cover: single system msg, multiple system msgs, no preceding user turn,
  `Text` vs `Blocks` content, idempotence, and flag-off = verbatim passthrough.

## Dependencies

- None blocking. Builds directly on the existing `strip_beta_options_from_request`
  machinery and the fallback-loop pristine-restore.

## NOT in scope

- **Rewedge upstream (Claude Code) to stop emitting role:system in messages.** Claude Code is already diverging by model (sonnet-4.6 folds it natively). The mux must bridge the gap for cross-model redirects regardless.
- **Full `MessageContent::Blocks` merge for the OpenAI guard** — the qwen/vllm path typically receives Text-only system entries. Guard handles Text arm; Blocks arm is a lower-priority follow-up.
- **Startup validation warning when a mapping redirects to a non-Anthropic provider without the flag set.** Deferred: adds config-cross-validation surface that isn't in the strip_beta_options idiom yet. Document the footgun instead.
- **Audit/replay contract for normalized requests.** The original (un-normalized) request is preserved in `request_json` (the `serde_json::from_value` source, never mutated), so a log/replay layer that captures `request_json` sees the original bytes. No extra contract needed.

## What already exists

- **`strip_beta_options_from_request`** (`src/server/mod.rs:294`) + `ModelMapping.strip_beta_options`/`strip_specific_beta` (`src/cli/mod.rs:116-121`) — exact sibling machinery the plan reuses. The normalizer lives next to it and composes with it.
- **`transform_openai_to_anthropic`** (`src/server/openai_compat.rs:92`) — already folds `role:"system"` into the top-level `system` field during OpenAI-inbound deserialization, so the `/v1/chat/completions` handler never has `role:"system"` in `messages`. The plan's original sketch referenced this handler's dispatch site (~1424) unnecessarily.
- **Per-attempt pristine-restore** in `handle_messages`: each mapping iteration re-parses from `request_json.clone()` (`src/server/mod.rs:1673`), so normalization re-runs from scratch per fallback candidate — no double-wrap risk.
- **Prior learning: deactivation-3-fallback-loops** (confidence 9/10, 2026-05-19) — the codebase has three fallback loops that must all receive cross-cutting behavior. This review found the same class of miss (non-streaming arm at 1757 not mentioned in the plan).
