## Affected Paths/Code Entry Points
- `POST /v1/messages` — main message handler with passthrough auth
- `POST /v1/messages` (streaming) — `send_message_stream()` path
- `src/providers/anthropic_compatible.rs` — auth selection logic
- `src/server/mod.rs` — fallback loop + same-provider filter

## Auth Preservation Tests
1. Bearer token in `Authorization` header → verify forwarded to upstream unchanged
2. `X-API-Key` header → verify forwarded unchanged
3. Missing `Authorization` header → expect 401 response
4. Malformed bearer format (e.g., "Token xyz" instead of "Bearer xyz") → expect 401

## Model Rewrite Tests
5. Router rewrites model parameter → verify `caller_auth` unchanged after rewrite
6. `original_model` field appears in structured log when model is rewritten

## Fallback Routing Tests
7. Upstream returns 503 → same-family fallback provider tried → success
8. Upstream returns 503 → cross-family provider in fallback list → NOT tried (blocked by family check)
9. All same-family fallback providers fail → normalized error JSON returned (502/503)

## Error Categorization Edge Cases
10. Upstream 503 → fallback triggered
11. Upstream 401 from upstream → fallback NOT triggered, terminal error returned
12. Upstream 429 WITH `anthropic-ratelimit-requests-remaining` header → fallback triggered
13. Upstream 429 WITHOUT ratelimit headers → fallback NOT triggered (model-access denial, terminal)
14. Connection timeout → fallback triggered

## Streaming Path
15. `stream: true` request with `Authorization` header → verify auth forwarded in streaming path

## Backward Compatibility
16. Request with no `Authorization` header → internal OAuth flow still used (existing behavior)
17. Malformed request payload → rejected with same error as before (shape validation unchanged)

## Regression Check (compile-time)
- All existing `AnthropicRequest { ... }` struct literals must compile after adding `caller_auth: Option<String>` field
  - `src/server/mod.rs:806`
  - `src/server/openai_compat.rs:202`
  - `src/router/mod.rs:253`

## Critical Paths
- Passthrough bearer → provider → upstream: auth must not be replaced by internal OAuth at any point
- Family-field gate: cross-family fallback must be blocked even when same-family is unavailable
- Non-passthrough (internal OAuth) requests must be completely unaffected

## Notes
- Tests should mock the upstream provider endpoint (use `wiremock` or `mockito`) to verify forwarded headers
- Auth forwarding tests should check the actual `Authorization` header value received by the mock upstream, not just that no error occurred
