## Affected Pages/Routes
- `/v1/messages` (Anthropic-format handler) — the primary dispatch; both streaming and non-streaming arms must accept requests with mid-conversation `role:"system"` messages and normalize them before forwarding when the mapping flag is set.
- `/v1/chat/completions` (OpenAI-format handler) — `transform_openai_to_anthropic` already folds system→top-level, so the normalizer is a no-op here. The defense-in-depth guard in `openai.rs transform_request` must fold any residual `role:"system"` to user.

## Key Interactions to Verify
- Cross-model redirect: opus-4.8/sonnet-5 payload → sonnet-4.6 target (with flag=true) → no `role:"system"` on wire → 200
- Cross-model redirect: same payload → qwen/vllm target (OpenAI format) → no `role:"system"` in messages → 200
- Same-model passthrough: flag=false → bytes flow verbatim → cache preserved

## Edge Cases
- `role:"system"` at messages[0] (no preceding user turn) → folds into FOLLOWING user turn (not synthesized)
- Multiple `role:"system"` messages in one request → each independently merged, order preserved
- Content already wrapped in `<system-reminder>` → no double-wrap (idempotence)
- Empty/whitespace `role:"system"` content → drop cleanly, no empty user block
- No `role:"system"` present → no-op, bytes unchanged
- Top-level `system` blocks with `cache_control` → untouched
- No-mapping path (direct provider lookup) → unconditional normalize

## Critical Paths
- Non-streaming `/v1/messages` with `role:"system"` redirected to sonnet-4.6 (regression — this arm was missed in the original plan)
- OpenAI-format provider receiving `role:"system"` after the flag is off (defense-in-depth guard in `openai.rs`)
