## Affected Pages/Routes
- `/admin?tab=providers&view=add` - Add provider flow needs new rate-limit fields, default values, and save behavior.
- `/admin?tab=providers` - Provider list/edit flow needs to show existing values after reload and when reopening a provider.
- Save All / Save & Restart actions - Confirm the new settings persist to server config and survive restart.

## Key Interactions to Verify
- Add a provider with `rate_limit_rpm` and `rate_limit_max_wait_ms` set, then save and confirm the values stay in local state.
- Edit an existing provider, confirm the fields prefill, clear them to disable rate limiting, then save.
- Change auth type or provider type and confirm the rate-limit fields are not lost.
- Use Save All and Save & Restart after editing, then confirm the values are still present after reload.

## Edge Cases
- Blank rate-limit fields on edit should disable rate limiting.
- `rate_limit_rpm = 0` should be rejected or surfaced as an error state, not silently saved.
- `rate_limit_max_wait_ms` should only matter when rate limiting is enabled.
- Reopening the same provider after navigating away should show the saved values, not defaults.

## Critical Paths
- Add NVIDIA NIM with a rate limit, save, restart, and verify the setting survives the full round-trip.
- Edit an existing provider to clear its rate limit, save, restart, and verify the config no longer contains the fields.
