## Problem Statement

claude-code-mux supports Anthropic, OpenAI (device/redirect), and Gemini (browser redirect) OAuth flows. GitHub Copilot subscribers have access to GPT-4o, Claude, and other models via their Copilot subscription but cannot route through mux because Copilot uses a distinct device-code-based auth with a two-stage token exchange. Adding a dedicated `copilot` provider_type unlocks Copilot's entire model roster for any Anthropic-API-compatible client (Claude Code, etc.) without additional API keys.

## What Makes This Cool

A GitHub Copilot subscriber can route Claude Code requests through `api.individual.githubcopilot.com` using their existing subscription — same models (GPT-4o, Claude Sonnet, etc.) with no separate API key. The Copilot bearer token is encoded with the exact API URL (`proxy-ep` field), so the base URL is dynamic per-user and parsed directly from the token payload.

## Constraints

1. GitHub's device code flow requires polling — not a redirect. The server polls `/login/oauth/access_token` at the interval specified by GitHub's device code response (default 5s), with `slow_down` error handling (+5s per occurrence), until the user authorizes or the `expires_in` deadline is reached (~15 min / 900s). Expired device codes require restarting the entire flow.
2. Copilot bearer tokens expire in ~30 minutes. The stored GitHub OAuth access token is used to refresh them via `GET https://api.github.com/copilot_internal/v2/token`. Concurrent refresh races must be prevented via `Arc<Mutex<()>>` or `tokio::sync::Mutex` at the provider level — two simultaneous requests must not both attempt refresh.
3. Required request headers: `Editor-Version: vscode/1.107.0`, `Editor-Plugin-Version: copilot-chat/0.35.0`, `Copilot-Integration-Id: vscode-chat`, `Openai-Intent: conversation-edits`, `X-Initiator: user` (for Claude Code usage, this is always `"user"` since the Anthropic API requires requests end with a user message).
4. The API base URL must be extracted from the bearer token's `proxy-ep=...` field (semicolon-delimited pairs). Use prefix-strip: `proxy-ep=proxy.X` → `api.X`. Fallback: `https://api.individual.githubcopilot.com`.
5. The admin UI device-code login uses a new two-step modal: (a) show `user_code` + `verification_uri` with "I've authorized" button, (b) clicking "I've authorized" calls `/api/oauth/copilot-exchange` which then polls GitHub (with SSE or short-timeout). The existing `/api/oauth/authorize` + `/api/oauth/exchange` pattern does not fit — the exchange endpoint for copilot must initiate and complete the GitHub polling, not just exchange a code.
6. Enterprise GitHub (company.ghe.com) is out of scope for this iteration.

**Naming convention:** `provider_type = "copilot"` in TOML config and `registry.rs`. The new OAuth endpoints (`/api/oauth/copilot-start`, `/api/oauth/copilot-exchange`) are named specifically for copilot and do not use an `oauth_type` parameter — they are separate routes, not branches of the existing `/api/oauth/authorize` + `/api/oauth/exchange` handlers. The existing handlers are not modified for copilot.

## Premises

1. Copilot API is OpenAI Chat Completions compatible at `{base_url_from_token}/chat/completions`
2. Auth is 3-step: device_code → GitHub OAuth access_token → Copilot bearer token (30min TTL)
3. A dedicated `copilot` provider_type is required — the auth model doesn't fit existing OAuth wiring
4. `refresh_token` field in TokenStore stores the GitHub OAuth access_token; `access_token` field stores the short-lived Copilot bearer token
5. Required Copilot request headers must be injected on every request, not just auth
6. Proxy-ep URL parsing is required for correct request routing

## Approaches Considered

### Approach A: Dedicated CopilotProvider (Chosen)
New `src/providers/copilot.rs` that implements `AnthropicProvider`. New `src/auth/github_copilot.rs` for the device code flow and token refresh. Admin UI gets a new device code display modal. The provider extracts the API base URL from the bearer token on each request refresh, injects required Copilot headers, and routes to `{base_url}/chat/completions` using the existing OpenAI Chat Completions request format.

- Effort: M (4-6 hours)
- Risk: Medium (device flow polling is new to codebase)
- Reuses: `OpenAIRequest`/`OpenAIResponse` structs, `AnthropicRequest` → OpenAI conversion logic from `openai.rs`, existing `TokenStore`, existing `ProviderRegistry`

### Approach B: Extend Existing OAuth Handlers (Hybrid)
Add a `github-copilot` branch to `oauth_handlers.rs`. The server starts the device flow, returns `{user_code, verification_uri}` as if it were an OAuth redirect URL. Admin UI opens the browser to GitHub's device page. Polling happens server-side when `/api/oauth/exchange` is called.

- Effort: M (3-5 hours)
- Risk: Low (minimal new code)
- Con: Device flow semantics don't match the existing redirect-based OAuth UI well; UX is confusing

### Approach C: Dedicated Device-Flow API with SSE
New dedicated endpoints with SSE streaming for live auth status. Richest UX but most new infrastructure.

- Effort: L (6-10 hours)
- Risk: Medium (SSE is new to codebase)

## Recommended Approach

**Approach A: Dedicated CopilotProvider**

Clean separation, closest to the gsd-2 reference implementation, testable in isolation. The device code polling complexity is contained inside `src/auth/github_copilot.rs`.

**Token storage strategy:**
```
OAuthToken {
  provider_id: <config.name>,              // e.g., "copilot" or "my-copilot" — matches the ProviderConfig name
  access_token: "<copilot_bearer_token>",  // short-lived (~30min)
  refresh_token: "<github_oauth_token>",   // long-lived GitHub OAuth access token, used to refresh bearer
  expires_at: <bearer_token_expiry>,       // ~30min from last refresh
  enterprise_url: None,
  project_id: None,
}
```

On `refresh_copilot_token`: update `access_token` and `expires_at` using the new values from `copilot_internal/v2/token` response. `refresh_token` and `provider_id` remain unchanged. Save via `token_store.save(updated_token)` (full overwrite, same key).

**Base URL storage:** Extract `proxy-ep` from `access_token` on each request (re-parse, no extra storage). The parse is a cheap string scan. Fallback to `https://api.individual.githubcopilot.com` if the field is absent.

## Key Implementation Notes

**Device code poll loop** (inside `poll_for_github_token()` — called by `copilot-exchange` endpoint):
```
- Use interval from device code response (not hardcoded 5s)
- On "authorization_pending": sleep interval, continue
- On "slow_down": interval += 5s, sleep, continue
- On "expired_token": return Err("device_code_expired") — endpoint returns {status: "expired"}
- Hard timeout: 60s per copilot-exchange call — returns {status: "pending"} if not yet authorized
  (Admin UI re-calls copilot-exchange until status == "success" or total elapsed > expires_in)
```

**Copilot streaming format:** The `api.individual.githubcopilot.com` endpoint returns standard OpenAI SSE format (`data: {...}\n\n` with `data: [DONE]\n\n` terminator). No additional event types beyond standard OpenAI streaming. The existing `openai.rs` streaming code can be reused as-is.
```
GET https://api.github.com/copilot_internal/v2/token
Headers: Authorization: Bearer {github_oauth_token}
         Editor-Version: vscode/1.107.0
         Copilot-Integration-Id: vscode-chat
         User-Agent: GitHubCopilotChat/0.35.0
Response: { token: string, expires_at: number }
```

**Base URL extraction** (parse on bearer token load; store alongside the token or re-parse on each request):
```
token format: tid=...;exp=...;proxy-ep=proxy.individual.githubcopilot.com;...

// Prefix-strip only — not a general substring replace:
let api_host = proxy_ep
    .strip_prefix("proxy.")
    .map(|s| format!("api.{}", s))
    .unwrap_or_else(|| proxy_ep.to_string());
let base_url = format!("https://{}", api_host);
// Fallback if proxy-ep field absent: "https://api.individual.githubcopilot.com"
```

**Required per-request headers:**
```
Editor-Version: vscode/1.107.0
Editor-Plugin-Version: copilot-chat/0.35.0
Copilot-Integration-Id: vscode-chat
Openai-Intent: conversation-edits
X-Initiator: user   // always "user" for Claude Code chat (API requires user-last messages)
```

**`count_tokens` implementation:** Delegate to tiktoken-based estimation identical to `OpenAIProvider`. `tiktoken_rs` is already in `Cargo.toml` (used by `openai.rs`). No new dependency needed.

**`supports_model` implementation:** Match against the `models` list from `ProviderConfig`, same as `OpenAIProvider`. Return `true` if the model name is in the list.

**Concurrent refresh guard** (inside `CopilotProvider`):
```rust
struct CopilotProvider {
    refresh_lock: Arc<tokio::sync::Mutex<()>>,
    // ...
}
// In get_valid_copilot_token():
//   1. Check token expiry without lock (fast path)
//   2. If expired: acquire refresh_lock, re-check expiry (second waiter skips refresh if first already refreshed), then call refresh_copilot_token()
```

### 4. Add `startCopilotFlow()` function

New function, added after `startOAuthFlow()`:

```js
async function startCopilotFlow() {
    const providerName = document.querySelector('input[name="provider_name"]').value || "copilot";

    try {
        // Step 1: Start device flow
        const response = await fetch("/api/oauth/copilot-start", {
            method: "POST",
            headers: { "Content-Type": "application/json" },
            body: JSON.stringify({ provider_id: providerName }),
        });
        if (!response.ok) throw new Error("Failed to start Copilot auth");
        const { user_code, verification_uri, device_code, expires_in, interval } = await response.json();

        // Step 2: Show device code modal
        document.getElementById("oauth-step-1").classList.add("hidden");
        document.getElementById("oauth-step-2").classList.remove("hidden");

        // Replace step 2 content with device code UI
        document.getElementById("oauth-step2-instructions").innerHTML = `
            <li>
                Go to <a href="${escapeHtml(verification_uri)}" target="_blank" class="text-blue-600 underline">${escapeHtml(verification_uri)}</a>
                (opening automatically...)
            </li>
            <li>Enter code: <strong class="font-mono text-lg bg-gray-100 px-2 py-1 rounded">${escapeHtml(user_code)}</strong></li>
            <li>Log in to GitHub and authorize</li>
            <li>Click "I've Authorized" below</li>
        `;

        // Auto-open GitHub device page
        window.open(verification_uri, "GitHub Copilot Auth", "width=600,height=800");

        // Store device_code and metadata for the exchange step
        sessionStorage.setItem("copilot_device_code", device_code);
        sessionStorage.setItem("copilot_provider_id", providerName);
        sessionStorage.setItem("copilot_expires_at", String(Date.now() + expires_in * 1000));

        // Wire "Complete OAuth" button to completeCopilotFlow (not completeOAuthFlow)
        const completeBtn = document.getElementById("oauth-complete-btn");
        completeBtn.textContent = "I've Authorized";
        completeBtn.onclick = completeCopilotFlow;

        notifySuccess("Enter the code on GitHub, then click 'I've Authorized'.");
    } catch (error) {
        notifyError(`Failed to start Copilot auth: ${error.message}`);
    }
}
```

### 5. Add `completeCopilotFlow()` function

```js
async function completeCopilotFlow() {
    const deviceCode = sessionStorage.getItem("copilot_device_code");
    const providerId = sessionStorage.getItem("copilot_provider_id");
    const expiresAt = parseInt(sessionStorage.getItem("copilot_expires_at") || "0");

    if (!deviceCode || !providerId) {
        notifyError("Session expired. Please restart the flow.");
        return;
    }

    if (Date.now() > expiresAt) {
        notifyError("Device code expired. Please start the flow again.");
        document.getElementById("oauth-step-1").classList.remove("hidden");
        document.getElementById("oauth-step-2").classList.add("hidden");
        return;
    }

    notifySuccess("Checking authorization...");

    // Poll copilot-exchange (each call polls GitHub server-side for up to 60s)
    while (Date.now() < expiresAt) {
        try {
            const response = await fetch("/api/oauth/copilot-exchange", {
                method: "POST",
                headers: { "Content-Type": "application/json" },
                body: JSON.stringify({ provider_id: providerId, device_code: deviceCode }),
            });
            if (!response.ok) throw new Error("Exchange request failed");
            const data = await response.json();

            if (data.status === "success") {
                document.getElementById("oauth-step-2").classList.add("hidden");
                document.getElementById("oauth-step-3").classList.remove("hidden");
                sessionStorage.setItem("oauth_provider_id", providerId);
                notifySuccess(`GitHub Copilot authenticated! Token saved for ${providerId}`);
                return;
            } else if (data.status === "expired") {
                notifyError("Device code expired. Please start the flow again.");
                document.getElementById("oauth-step-1").classList.remove("hidden");
                document.getElementById("oauth-step-2").classList.add("hidden");
                return;
            }
            // status === "pending": loop continues (server already waited up to 60s)
        } catch (error) {
            notifyError(`Exchange failed: ${error.message}`);
            return;
        }
    }

    notifyError("Authorization timed out. Please start the flow again.");
}
```
