+ X-Request-Id (per-call UUID) + force-refresh on 401 + network error single retry.

## Affected Paths / Routes

## Key Interactions to Verify

1. **Long session (>10 turns)** — POST several consecutive messages through the Copilot
   provider. Verify no 400 Bad Request errors appear (before fix, appears at turn 3-6).

2. **401 force-invalidation** — Set the Copilot token's expires_at to a past timestamp
   in the token store. Trigger a request. Verify a fresh token is fetched (no double-401).

3. **Network retry** — Simulate a connection reset (e.g., proxy port block, then unblock).
   Verify the request succeeds on retry within ~500ms.

## Edge Cases

- Provider restart: VScode-SessionId and VScode-MachineId change — verify no 400 on first
  request after restart
- `try_clone()` returns None: verify fallback to propagating the original error (no panic)
- Concurrent requests racing on stale token: only one refresh should happen (lock serializes)

## Critical Paths

1. Copilot streaming response: end-to-end from Claude Code → proxy → GitHub Copilot API
2. 401 recovery: stale-token request → 401 → force-refresh → retry → success
