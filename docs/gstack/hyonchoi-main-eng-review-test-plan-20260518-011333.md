## Affected Pages/Routes
- `/` (admin UI) — all admin actions trigger notify/confirm/prompt dialogs

## Key Interactions to Verify

### Notifications (notify / notifySuccess / notifyError / notifyWarning)
- Save config → green toast appears top-right, auto-dismisses after 3s
- Delete action error → red toast appears
- Toast is dismissable by clicking X before timeout
- notifyError with an error.message containing `<b>bold</b>` → renders as plain text (NOT bold)

### Delete confirmations (confirm → UIkit.modal.confirm)
- Click "Delete" on a provider → modal appears with correct message
- Click Cancel in modal → provider NOT deleted
- Press Escape in modal → provider NOT deleted
- Click OK in modal → provider deleted, success toast shown
- Same for delete model, delete OAuth token

### Restart confirmations
- Click "Restart Server" → modal appears
- Cancel → no restart
- Confirm → server restarts, success toast shown
- Click "저장 & 재시작" → modal with "Save all settings and restart. Are you sure?"

### API key prompt (prompt → UIkit.modal.prompt)
- Trigger a 401 (e.g. wrong API key in sessionStorage) → UIkit prompt modal appears
- Cancel prompt → original 401 response returned to caller (no crash)
- Enter valid key → request retried with new key, succeeds
- Enter empty string → `if (key)` guard fires, 401 returned (empty string is falsy)

## Edge Cases
- Provider name containing `<script>` in deleteOAuthToken confirm → message shows `&lt;script&gt;` (escaped)
- Rapid double-click on Delete button → only one modal shown (UIkit queues modals)
- CDN failure (UIkit not loaded) → console.error logged, notify() returns silently, no ReferenceError crash

## Critical Paths
- Save config → toast → no regression in save flow
- Delete provider → modal → confirm → provider removed → re-render correct
- Trigger 401 → UIkit prompt → enter key → successful retry
