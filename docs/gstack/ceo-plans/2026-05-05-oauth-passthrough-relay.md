## Definitions
- Same-provider boundary: fallback targets that share the same auth trust authority as the caller credentials.
- Trust metadata: provider registry fields that declare provider family and auth authority domain.
- Retry budget: maximum retry attempts per request and per provider within a bounded window.
- Replay harness: deterministic integration suite replaying representative requests against injected upstream failures.

Phase 1 trust authority rule:
- Compile-time provider-family map is the only source of truth in this slice.
- Runtime registry trust metadata is out of scope for Phase 1.

## Request/Fallback State Machine
```
RECEIVED
	-> AUTH_VALIDATED
	-> ROUTED
	-> UPSTREAM_SENT
	-> (UPSTREAM_OK) -> SUCCESS
	-> (UPSTREAM_RETRIABLE_ERROR) -> FALLBACK_ELIGIBILITY_CHECK
	-> (UPSTREAM_AUTH_OR_CLIENT_ERROR) -> TERMINAL_ERROR

FALLBACK_ELIGIBILITY_CHECK
	-> (same-provider + retry budget available + circuit closed/half-open) -> FALLBACK_SENT
	-> (otherwise) -> TERMINAL_ERROR

FALLBACK_SENT
	-> (FALLBACK_OK) -> SUCCESS
	-> (FALLBACK_ERROR and budget remains) -> FALLBACK_ELIGIBILITY_CHECK
	-> (budget exhausted or circuit open) -> TERMINAL_ERROR
```

Invalid transitions to block:
- AUTH_VALIDATED -> FALLBACK_SENT (must route and attempt primary first)
- UPSTREAM_AUTH_OR_CLIENT_ERROR -> FALLBACK_ELIGIBILITY_CHECK (no fallback on 401/403/4xx client errors)
- CIRCUIT_OPEN -> FALLBACK_SENT (must fail fast)

## Error and Rescue Registry

| Method/Codepath | What can go wrong | Exception class | Rescued? | Rescue action | User sees | Logged |
|---|---|---|---|---|---|---|
| Relay auth extraction | Missing/invalid Authorization header | AuthValidationError | Y | Return 401 with normalized message | Auth error | Y (request_id, provider_origin, auth_preserved=false) |
| Primary upstream call | 5xx/429 response | UpstreamRetriableError | Y | Evaluate same-provider fallback + retry budget | Transparent fallback or terminal upstream error | Y (error_class, upstream_provider, fallback_triggered) |
| Primary upstream call | 401/403 from upstream | UpstreamAuthError | Y | No fallback; return terminal error | Auth denied | Y (error_class=auth_error, fallback_triggered=false) |
| Upstream networking | Timeout/TLS/connectivity failure | UpstreamNetworkError | Y | Same-provider fallback if eligible | Transparent fallback or terminal upstream error | Y (error_class, retry_count, circuit_state) |
| Fallback execution | Budget exhausted/circuit open | FallbackExhaustedError | Y | Return normalized terminal error contract | Service unavailable message | Y (fallback_attempted=true, providers_tried) |
| Registry boundary check | Cross-provider candidate selected | TrustBoundaryViolationError | Y | Reject candidate, continue same-family only or fail | Terminal upstream error (no auth translation) | Y (provider_origin, candidate_provider, blocked=true) |

Rules:
- No catch-all handler without explicit reclassification into a known error class.
- Every rescued error must map to user-visible contract + structured logs.
- Auth/client errors never trigger fallback.

Retry classification refinement:
- Replace coarse status-class fallback decisions with adapter-level normalized classes:
	- retryable
	- non_retryable
	- auth_fatal
	- quota_fatal
- Each provider adapter must map upstream responses to one of these classes with mandatory conformance tests in this slice.

Phase 1 adapter coverage scope:
- Mandatory conformance applies to core adapters in active passthrough path first.
- Long-tail adapters are explicitly deferred to the next patch train with compatibility fallback behavior documented.

## Data Flow (Shadow Paths)
```
INPUT -> AUTH VALIDATION -> ROUTING TRANSFORM -> PRIMARY UPSTREAM -> OUTPUT
	|          |                   |                   |               |
	|          |                   |                   |               +-> stale/partial output handling
	|          |                   |                   +-> timeout/5xx/429 -> fallback decision
	|          |                   +-> wrong model mapping / missing provider family
	|          +-> malformed/missing header -> terminal auth error
	+-> nil/empty payload checks -> validation error
```

Path requirements:
- Happy path: preserved auth + routed model + primary success.
- Nil path: missing auth or required payload returns explicit validation/auth error.
- Empty path: empty content/tool arrays handled with deterministic validation response.
- Error path: retriable upstream errors trigger bounded same-provider fallback; non-retriable errors terminate.

Idempotency boundary:
- Fallback/retry is allowed only before irreversible downstream write boundaries.
- For streaming/partial-write contexts, disable fallback after first irreversible emission and return terminal error on subsequent failure.

## Interaction Edge Cases (Service Behavior)

| Interaction | Edge case | Handled? | Handling |
|---|---|---|---|
| Upstream call | Timeout while request in-flight | Yes | Retry-budgeted fallback with jitter/backoff |
| Fallback loop | Retry request while circuit open | Yes | Fail fast terminal error |
| Boundary check | Candidate fallback in wrong provider family | Yes | Reject candidate and continue safe path |
| Concurrent failures | Multiple requests hit failing provider simultaneously | Planned | Circuit-breaker + bounded retries |
| Exhaustion | All fallback targets fail | Yes | Normalized terminal error with attempts metadata |

## Code Quality Guardrails
- DRY rule: trust-boundary checks and fallback-eligibility policy live in one shared helper path, not duplicated across providers.
- Complexity rule: new auth/fallback methods should stay below high branch fan-out; split helpers when branching exceeds practical reviewability.
- Naming rule: error classes and telemetry fields must be semantic (`UpstreamAuthError`, `TrustBoundaryViolationError`) and not transport-leaky.
- Catch-all rule: no broad catch without explicit remap to a known error class + context-rich log event.
- Diff discipline: behavior fixes and unrelated refactors must not be mixed in one change unit.

## Circuit-Breaker and Retry Parameterization
- Defaults:
	- Retry attempts: max 2 fallback retries per request.
	- Backoff: jittered exponential starting at 100ms, max 2s.
	- Circuit-breaker: trip when failure ratio >=50% over 20 requests, cooldown 30s, then half-open probe.
	- Breaker key scope: origin_provider + target_provider + model_class.
	- Aggregate retry budgets: enforce node-level and cluster-level retry token ceilings with fail-fast when exhausted.
- Config surface: explicit router/resilience settings with bounded safe ranges.
- Override policy: env/config overrides allowed within guardrails only.

	-> Relay Entry (auth extraction/validation)
